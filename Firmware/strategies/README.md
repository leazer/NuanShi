# 暖时采暖策略包

`nuanshi-v1.json` 是设备内置的第一版，也可单独安装。登录设备网页，在「策略更新」选择 JSON 文件并点「安装策略」。可先下载当前策略留作回退。安装完成后设备会记录策略版本，下次决策开始使用新规则。修改规则时请更新 `revision`，方便对照日志。

## 文件格式

- `schema` 固定为 `1`，`revision` 是 1 到 65535 的整数。
- `hold_minutes` 为两次常规调档的最短间隔，允许 60 到 180 分钟。
- `forecast_minutes` 为趋势外推时间，允许 0 到 90 分钟。外推对温度的修正量限制在 ±0.45 °C。
- `rules` 含 1 到 8 条规则，从上往下执行第一条匹配的规则。每条的 `all` 含 1 到 3 个必须同时成立的条件。每个条件包含 `metric`、`op` 和整数 `tenths`。比较符可用 `>=` 和 `<=`。
- `gear` 为档位的十分位整数，如 `20` 表示 2.0 档，允许 `5` 到 `40`。也可写 `"low"` 用设置的低温档，或写 `"hold"` 保持上次指令。无匹配时保持上次指令，启动且尚无指令时用低温档。

| `metric` | 含义 |
| --- | --- |
| `forecast_deficit` | 目标温度减去按室温趋势外推的温度，单位 °C |
| `indoor_deficit` | 目标温度减当前室温，单位 °C |
| `trend` | 最近约 30 分钟的室温变化速率，单位 °C/小时 |
| `outdoor` | 昌平室外温度，单位 °C |
| `gear` | 最近一次发出的档位指令 |

例如 `"metric":"forecast_deficit","op":">=","tenths":6` 表示预计欠温至少 0.6 °C。室外读数或上次档位缺失时，依赖该值的条件不匹配。

## 主固件行为

自动模式需要有效标定和时间同步。非采暖时段和温度计确认失联时走低温档，室温达到目标以上 0.5 °C 时可提前回低档。室温读数发生突变后，设备等待 30 分钟再按新的稳定测点决策。采暖起止时间相同表示全天低温档。档位按标定换算，输出脉宽限制在 500–2500 µs。

规则包可以独立调整判断条件、优先级和档位。新增传感器、指标或保护逻辑需要更新主固件。
